# 조사 자료 읽는 순서

1. [출처 대장](source-register.md): 공개 작성 스킬·논문·개발 프로세스·규격·Confluence 블록 기능의 관찰·적용·한계.
2. [구조화 출처](sources.json): 같은 외부 자료의 기계 판독 메모. 내부 Zotero 키·개인 경로 없이 제공한다.
3. [템플릿 목적 대장](template-purpose-catalog.csv): 당시 연결에서 읽은 284개 항목의 형태·목적에 대한 분석. 원문 본문·내부 API ID/URL은 제외한다. 같은 이름의 중복 항목과 매크로 보조 항목이 포함되므로 284개의 독립 실무 양식으로 해석하지 않는다.
4. [설계 결정](../docs/adr/0001-entrypoint.md), [요구 추적](../docs/requirements-traceability.md): 자료에서 관찰한 것과 이번 자체 설계를 연결한다.

Double Diamond의 Discover에서 프로세스·문서·템플릿·블록을 넓게 조사하고, Define에서 현재 문제를 의미·의도 보존과 다음 작업의 입력 연결로 좁혔다. Develop에서는 여러 진입점/단일 큰 파일/조건부 참조를 비교했고, Deliver에서는 비공개 구현 후보·확인·잔여 조건을 인계한다. 이 적용 흐름은 프로젝트의 자체 설계이며 사용자 조사나 효과 측정을 수행했다는 뜻은 아니다.

ISO 자료는 기존 조사에서 공개 개요·판본·상태를 확인한 범위다. 유료 전문의 의무 조항을 모두 읽거나 준수 인증을 수행하지 않았다. 현재 스킬은 특정 개발 프로세스나 284개 템플릿의 전문을 강제하지 않는다.
