# 한국어 표현의 문맥

핵심 SKILL.md의 의미 보호 계약을 적용하면서 해석과 말투를 판단한다. 아래는 일괄 치환 규칙이 아니다.

## 생략과 호응

독자가 주체를 알 수 있는 “확인했습니다”는 자연스러울 수 있다. 매 문장에 “저는/우리는”을 넣지 않는다. “운영팀과 개발팀이 확인했다. 그쪽에서 게시했다”에서 게시 주체를 밝혀 달라는 요청은 자료만으로 해결되지 않는다. 게시한 팀만 확인하며 임의로 한 팀을 선택하지 않는다.

긴 문장에서는 주어와 서술어, 수식 범위가 맞는지 확인한다. 문장을 나눌 때 조건절이 다음 문장에 계속 적용되는지 살핀다. “외부 계정에 적용하며 내부 계정은 제외한다”를 “계정에 적용한다”로 줄이지 않는다.

## 부정·양태·정도

| 표현 | 구분할 해석 | 편집 판단 |
|---|---|---|
| 모두 승인된 것은 아니다 | 전체 승인의 부정 | 승인된 항목이 하나도 없다는 뜻으로 바꾸지 않음 |
| 아직 확인하지 못했다 | 확인 상태 | 문제없음·확인 완료로 바꾸지 않음 |
| 바뀔 수 있다 | 변화 가능성 | 실제 변경으로 강화하지 않음 |
| 사용할 수 있다 | 능력·가능·허용 중 문맥에 따른 뜻 | 뜻이 모호하면 허용되었다고 단정하지 않음 |
| 완료했다 | 실제 완료 주장 | 신중하게 보이려고 완료했을 수 있다고 약화하지 않음 |
| 가능 여부를 알려 달라 | 질문 | 실행해 달라는 지시나 실행 약속으로 바꾸지 않음 |

“~할 수 있다”, “~로 보인다”, “~일 것으로 예상한다”를 군더더기로 취급해 자동 삭제하지 않는다. 관찰·추정·제안이 달라지는지 먼저 확인한다. “설정 변경 뒤 회복됐다”는 시간 순서이며 원인이 검증되지 않았다면 “설정 변경으로 회복됐다”로 바꾸지 않는다.

## 격식과 목소리

짧은 Slack 문구는 공손한 해요체·합니다체·간단한 문장형 모두 가능하다. 제공된 관계와 사용자가 요청한 격식을 따른다. 업무 글이라는 이유만으로 과도한 사과·완곡어·명사형을 더하지 않는다.

“시간 되실 때 초안만 봐주실 수 있을까요?”를 다듬어도 시간 여유·초안 한정·가능 여부 질문을 유지한다. 긴급 마감 요청으로 바꾸지 않는다. 반대로 사용자가 정한 긴급성·기한은 공손함을 이유로 흐리지 않는다.

반복·피동·명사화·접속사는 의미와 기능을 보고 판단한다. 명확한 행위자가 있으면 동사 중심으로 정리할 수 있지만 책임 주체가 미확인인 피동문에 가짜 주체를 넣지 않는다. 강조나 병렬 구조에 필요한 반복은 유지한다.

맞춤법·띄어쓰기의 확정 판단이 필요하고 자신이 없으면 권위 있는 현행 어문 규범을 확인한다. 확인하지 않은 규범을 공식 규칙이라고 주장하지 않는다. 기술 식별자와 정확한 인용은 표기 교정 대상에서 분리한다.
