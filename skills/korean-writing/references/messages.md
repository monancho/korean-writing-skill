# 짧은 업무 메시지

메시지 목적에 맞게 핵심과 필요한 후속 행동을 빠르게 찾게 한다. 한 문장으로 충분하면 제목·표·여러 절을 만들지 않는다. 실제 담당자·기한·승인·결과가 없으면 추가하지 않는다.

| 목적 | 정보 순서 후보 | 확인할 경계 |
|---|---|---|
| 공유 | 전달할 사실 → 적용 범위/제한 → 필요 시 참고 링크 | 읽는 사람의 행동이 없으면 요청을 덧붙이지 않음 |
| 요청 | 대상 행동/확인 질문 → 필요한 배경·자료 → 정해진 기한 | 가능 여부 질문과 수행 지시를 구분 |
| 진행 업데이트 | 현재 상태 → 완료/미완료·차단 → 다음 계획 | 다음 계획을 수행 완료로 쓰지 않음 |
| 결정 요청 | 정확한 질문 → 권장안·대안/영향 → 필요한 답 | 요청을 받은 사실과 유효한 승인 응답을 구분 |
| 결정 공유 | 실제 결정·주체·범위 → 영향 → 확정된 후속 행동 | 제안·토론을 결정으로 승격하지 않음 |

가상 공유: “자료 12건 중 8건을 확인했습니다. 확인한 범위에서는 인용 오류를 발견하지 못했으며, 접근하지 못한 4건은 미확인입니다.” 전체 확인이나 오류 0건을 주장하지 않는다.

가상 요청: “이번 주에 초안 검토가 가능한지 알려 주세요.” 제공된 요청은 가능 여부 확인이다. “이번 주까지 검토를 완료해 주세요”로 바꾸면 행동과 기한이 달라진다.

이전 메시지가 제공되면 현재 변경·같은 사건·필요 링크를 고려할 수 있다. 조직의 보고 채널·스레드·알림 절차는 실제 사용자 위임과 그 환경의 지침을 따른다. 이 파일에 특정 회사의 Slack 운영 절차를 일반 규칙으로 넣지 않는다.

실제 발송을 요청한 경우 문구와 발송 결과를 분리한다. 현재 도구·대상·위임이 확인된 경우 해당 환경의 절차를 따르며, 문구만 준비한 상태를 게시 완료라고 보고하지 않는다.
