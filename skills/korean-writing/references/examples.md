# 자체 가상 예시

모든 입력과 결과는 설명을 위해 만든 가상 자료다. 실제 회사 문서·사용자 발언·시험 로그가 아니다. 핵심 SKILL.md의 의미 계약을 문맥에 적용하는 예이며 정답 문구를 강제하지 않는다.

| 요청·입력 | 가능한 결과 | 보호한 것 |
|---|---|---|
| 간결하게: 응답률은 20%에서 25%로 바뀌었다. | 응답률은 20%에서 25%로 바뀌었다. | 두 비율 유지. 요청 없는 계산·개선 방향 추가 없음 |
| 자연스럽게: 검토가 끝나면 게시 여부를 논의할 수 있다. | 검토를 마치면 게시 여부를 논의할 수 있다. | 검토 조건·논의 가능성. 게시 확정 아님 |
| 간결하게: 모두 승인된 것은 아니다. | 모두 승인된 것은 아니다. | 승인된 항목이 0개라는 뜻으로 바꾸지 않음 |
| 공손하게: 이번 주 검토가 가능한지 알려 주세요. | 이번 주에 검토가 가능한지 알려 주시겠어요? | 가능 여부 질문. 완료 요구·약속 아님 |
| 짧게 보고: 담당자는 설정이 원인일 것으로 예상했다. 원인 확인은 미완료. | 담당자는 설정을 원인으로 예상했으며, 원인 확인은 아직 끝나지 않았습니다. | 주장자·예상·미확인 |
| 한 문장 요약: 외부 사용자 대상, 내부 계정 제외, 검토 완료 시 도입 논의 가능. | 내부 계정을 제외한 외부 사용자를 대상으로, 검토를 마치면 도입을 논의할 수 있습니다. | 대상·예외·조건·논의 가능성 |
| 어색한 부분만: 초안 검토가 끝나면 게시 여부를 논의하겠습니다. | 초안 검토가 끝나면 게시 여부를 논의하겠습니다. | 이미 적절한 원문 유지 |

## 필수 정보만 확인하는 사례

입력: “운영팀과 개발팀이 확인했다. 그쪽에서 게시했다.” 요청: 게시 주체를 명확히 해 달라.

가능한 결과: “게시한 팀이 운영팀인지 개발팀인지 확인이 필요합니다. 확인한 두 팀은 그대로 두고 게시 주체만 확정하면 됩니다.” 자료에 없는 행위자를 만들어 넣지 않는다.

입력: 기한 없이 검토 요청 문구를 작성해 달라.

가능한 결과: “초안을 검토해 주시겠어요?” 기한이 필요하지 않으면 날짜 질문을 강제하지 않는다.

## 검토와 결정 기록

검토만 요청한 자료에서 한 절은 “검토 상태 미정”, 다른 절은 “검토 완료”이면 두 위치의 상태 충돌과 확인할 사항을 알려 준다. 전체 문서를 자동 재작성하거나 점수를 붙이지 않는다.

ADR 요청에 대안의 장단점과 권장안만 제공되면 맥락·판단 기준·대안·권장안·영향·확인 방법을 구성하고 “제안” 상태를 유지한다. 실제 결정자·채택일이 없으면 미정이며 승인된 결정이라고 쓰지 않는다.
