# 목적에 맞는 문서 구성

독자가 무엇을 이해·판단·실행해야 하는지 먼저 파악한다. 아래 정보는 목적에 필요한 후보이며 모든 문서에 같은 절을 강제하지 않는다. 이미 조직 양식이나 사용자 양식이 제공되면 그것을 우선하고 부족한 입력의 상태를 드러낸다.

| 목적 | 필요한 정보 후보 | 흔한 의미 오류 |
|---|---|---|
| 제안·기획 | 해결할 문제·대상/범위·근거·대안·권장안·영향·미결·다음 확인 | 기대 효과를 관찰된 효과로 씀 |
| 결정 기록·ADR | 맥락·판단 기준·대안·선택/권장·결정 상태/주체·영향·확인 방법 | 권장안을 승인·채택으로 표시 |
| 절차·사용 안내 | 목적·전제·필요 입력·순서·확인 결과·실패 시 행동 | 순서를 인과로, 미확인 단계를 실행 완료로 표시 |
| 상태 보고 | 대상·기준 시점·진행/완료·확인 범위·제한·다음 행동 | 일부 확인을 전체 성공으로 확대 |
| 설명·참조 | 독자 질문·핵심 개념·구분·정확한 조건/정의·필요 예시 | 설명을 수행 지시로 바꿈 |
| 회의·검토 기록 | 논점·실제 발언/관찰·결정·미결·확정된 후속 행동 | 논의된 행동에 가짜 담당/기한을 부여 |

핵심 결론이나 필요한 행동을 찾기 쉽게 두고 근거·조건을 바로 연결한다. 연구와 자체 권고가 함께 있으면 각 주장에 출처와 역할을 붙인다. 조건이 긴 자료를 한 문장으로 요약하라는 요청에서도 의미를 바꾸는 축약은 피하고, 길이 제한과 보호할 의미가 양립하지 않으면 그 지점을 설명한다.

## 양식을 채우는 기준

양식은 정보를 담는 구조다. 빈칸이 사실·승인·담당·날짜를 만들어 주지 않는다. 필수 항목의 입력이 없으면 “미정”, 사실 확인 전이면 “미확인”, 적용 대상이 아니면 “해당 없음”을 구분한다. 필요 없는 선택 항목은 제거할 수 있다.

ADR을 요청받으면 제안/검토 중/채택 등 제공된 상태를 보존한다. 번호나 제목이 있다고 승인된 결정이 되지 않는다. 실제 양식이 제공되면 구조를 따르고, 자체 양식을 제시할 때는 공식 템플릿을 그대로 적용했다고 주장하지 않는다.

Confluence의 패널·표·펼치기·탭 같은 기능은 필요한 정보를 읽기 쉽게 표현하는 수단이다. 현재 내용을 함께 갱신해야 하는 동기화와 당시 결정을 보존하는 기록을 구분한다. 기능별 권한·상태·렌더링을 확인하지 않고 지원하거나 동기화됐다고 쓰지 않는다. 특정 제품 블록을 일반 Markdown에 그대로 옮길 수 있다고 가정하지 않는다.

긴 문서는 구조와 유지 영역을 먼저 파악하고 의미가 완결되는 절 단위로 수정한다. 읽지 않은 절까지 검토했다고 표시하지 않는다. 부분 수정 후 전체 용어·높임·참조·조건 연결을 확인한다.
