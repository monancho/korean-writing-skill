# ADR-001 — 한 진입점과 조건부 참조

상태: 이번 구현에서 사용하는 기술 설계 기준. 장기 운영 정책·공개·효과 검증의 수락과 구분한다.

작성: Codex, 2026-10-12 Asia/Seoul. 사용자가 기존 문서를 기반으로 순차 구현을 명시했고 비공개 저장소 생성을 선택했다.

## 맥락과 판단 기준

작성·수정·검토는 공통으로 의미를 보호하지만 결과물은 다르다. 짧은 문구에 장문 공동 집필 절차를 강제하거나 모든 참조를 읽으면 요청보다 일이 커진다. 공통 규칙을 각 모드에 복제하면 개정 시 불일치가 생길 수 있다.

판단 기준은 공통 규칙의 일관성, 요청 모드의 구분, 필요한 내용만 읽기, 특정 회사·도구와 무관한 재사용이다.

## 대안과 선택

| 대안 | 이점 | 비용·조건 |
|---|---|---|
| 모드별 스킬 세 개 | 호출 목적을 구분하기 쉬움 | 공통 의미 규칙의 중복·모드 결합 시 중복 로딩 |
| 하나의 큰 파일 | 참조 누락이 적음 | 간단한 요청에도 장문 규칙을 전부 읽음 |
| 한 진입점과 조건부 참조 | 공통 규칙을 한 곳에서 관리하고 필요한 상세만 읽음 | 참조 선택이 실제 요청에 맞는지 확인 필요 |

세 번째 구성을 구현한다. `SKILL.md`에 공통 의미 계약·모드·불충분 입력·최종 대조를 두고, 문서·메시지·한국어 표현·근거·예시를 별도 참조로 둔다. 독자·목적·정보 순서의 짧은 공통 판단은 핵심과 문서 참조에 포함하므로 독립 `principles.md`는 만들지 않는다.

## 영향과 확인

지침만으로 파일 생성·외부 발송·승인 권한을 얻지 않는다. 모든 참조는 상대 경로이며 내부 운영 정책이나 계정 연결이 필요 없다. 불필요한 참조 강제, 공통 규칙 충돌, 필수 규칙 누락이 관찰되면 이 결정을 재검토한다.

현재 선택은 자체 설계 판단이다. 공개 사례의 모드 구분과 점진적 로딩에서 참고했으나 실제 개선 효과나 다른 대안보다 우월함을 검증하지 않았다. 출처별 관찰·적용·한계는 후속 출처 대장에 연결한다.
