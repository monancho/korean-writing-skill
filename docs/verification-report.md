# 검증 실행 보고와 결함 기록

작성·직접 확인: Codex, 2026-10-12 Asia/Seoul. 입력은 구현 판본과 기존 TC01–TC28이다.

## 실행 방법과 검증 수준

공식 quick_validate.py를 UTF-8 실행 모드로 수행하고, 자체 구성 검사·8개 손상 감지/무결성 시험·ZIP 생성을 실제 실행했다. Python 3.12의 Windows 로컬 환경에서 통과했다. 자동 검사는 UTF-8·참조·구성·배포 경계를 확인하며 글의 의미나 품질을 자동 판정하지 않는다.

작성자는 최종 핵심 지침과 필요한 참조를 읽고 기존 가상 요청에 직접 적용해 결과를 파일로 기록했다. 기대 조건을 알고 있는 같은 컨텍스트의 직접 대조다. 독립 검토·설치된 호스트의 자동 호출·보편 성능을 입증하지 않는다. 25개 문장·문서 사례, 2개 도구 없는 환경의 경계 사례, 1개 실제 파일 정적 확인을 구분한다.

원본 입력·보호 조건은 [cases.json](../tests/cases.json), 실제 기록한 결과는 [direct-application.json](../tests/observations/direct-application.json)이다. 가상 입력이 구체적인 A/B 내용·해결안·명령을 제공하지 않은 TC20/21/23에서는 없는 세부를 만들어 채우지 않았다. TC27은 제공된 “조건부 초안”을 조건·가능성의 경계로 한정해 관찰했으며 다양한 복합 모드 전수시험은 아니다.

## 발견·수정·재확인

| 사건 | 관찰 | 조치·현재 결과 |
|---|---|---|
| D-ENC-01 | cp949 기본 모드에서 공식 검사 UTF-8 읽기 실패 | python -X utf8로 실행하여 통과 |
| D-ENC-02 | 생성된 UI 메타데이터의 cp949 저장 | UTF-8 재작성·전체 파일 검사·비UTF-8 거부 시험 통과 |
| D-LINK-01 | 첫 Linux CI에서 아직 없는 verification-report.md 링크 발견 | 이 실제 보고를 작성하여 링크 목적지를 만들고 전체 구성 검사 재실행 |

첫 CI 실패는 숨기지 않고 [실패 실행](https://github.com/monancho/korean-writing-skill/actions/runs/38150065403)에 보존한다. 최종 HEAD CI 결과는 PR의 실제 Checks와 Jira 인계에 연결한다.

## 남은 확인

별도 컨텍스트의 독립 순방향 시험·사람 사용성 수락·다른 제품의 자동 선택은 수행하지 않았다. 외부 발송·DOCX/HWPX 제작·모델 간 비교·실사용 효과 측정·확정 일정·공개 전환·정식 릴리스도 이 결과에 포함하지 않는다. 직접 적용의 제한을 없애려면 실제 입력과 도구 범위를 정한 독립 실행이 필요하다.
