# 구현 계획

작성: Codex, 2026-10-12 Asia/Seoul. 이 문서는 최초 구현의 입력·범위·순서·파일 책임을 정한 기록이다. 확정 일정은 두지 않았다. 이후 변경과 실제 결과는 [구현 기록](implementation-record.md)에 연결한다.

## 구현할 범위

문제 정의, 입출력 명세, 의미 보호 계약, 요구사항 추적, 가상 검증 사례를 입력으로 사용한다. 요구사항은 R1–R9, 의미 보호 조건은 K01–K12, 처리 분기는 B01–B11이다. 이 식별자는 개발 기록에 쓰며 모든 사용자 결과에 출력하지 않는다.

구현 대상은 지침형 스킬, 자체 한국어 가상 예시, 패키지 검사, 사용 안내와 공개 준비 인계다. 문서 파일 엔진·발송 자동화·점수표·사용자 효과 실험은 포함하지 않는다.

## 순서와 인계

| 단계 | 입력 | 산출물 | 다음 단계에 넘길 것 |
|---|---|---|---|
| 설계 | R/K/B·문서 규격 | ADR·파일 책임·구현 계획 | 모드·참조 책임·입력 부족 처리 기준 |
| 구현 | 설계 기준 | SKILL.md·참조 5개·UI 메타데이터 | 유효한 메타데이터·경로·가상 예시와 정확한 판본 |
| 검증 | 구현 판본·TC01–TC28 | 구성 검사·직접 적용·결함/미검증 기록 | 기대와 실제 관찰을 구분한 결과 |
| 사용 안내 | 실제 파일·검증 결과 | README·설치/호출 안내·출처 대장 | 기능·명령·파일이 대응하는 공개 후보 |
| 공개 준비 | 후보·검증·자료 목록 | 라이선스 권장안·자료 범위·잔여 조건 | 실제 공개·라이선스·정식 릴리스의 결정 대상 |

설계 기록은 MADR의 맥락·기준·대안·선택·영향·확인 흐름을 참고한다. 구현 계획과 요구사항 추적 표는 프로젝트에 맞게 구성했다. 검증은 입력·판본·방법·출력·관찰·결함·제한을 연결하고, 공개 결정은 대상·선택·영향·재개 조건을 기록한다. 외부 템플릿 본문은 배포 패키지에 복제하지 않는다.

## 남길 근거

변경은 단계별 커밋으로 남기고 결함은 관찰·수정·재확인을 연결한다. 실제 검사와 작성자 직접 적용을 구분하며 독립 검토·자동 선택·다른 환경·효과 입증으로 확대하지 않는다. 외부 공개 자료는 링크·자체 요약·판본을 포함하고 내부 문서·Slack 원문·개인 경로·논문 PDF·타인 스킬 원문은 제외한다.
