# 구현 계획과 단계별 인계

작성: Codex, 2026-10-12 Asia/Seoul. 확정 일정은 없다.

## 입력과 범위

기존 문제 정의·입출력 명세·의미 보호 계약·요구사항 추적·가상 검증 사례를 구현 입력으로 사용한다. 요구사항은 R1–R9, 의미 보호 조건은 K01–K12, 처리 분기는 B01–B11이다. 식별자는 개발 기록에서 사용하며 사용자 결과에 일괄 출력하지 않는다.

이번 결과는 지침형 스킬, 자체 한국어 가상 예시, 패키지 검사, 사용 안내와 공개 준비 인계다. 문서 파일 엔진·발송 자동화·점수표·사용자 효과 실험은 구현 범위가 아니다.

## 순서와 산출물

| 단계 | 입력 | 실제로 만들 결과 | 확인·다음 입력 |
|---|---|---|---|
| 설계 | 기존 R/K/B·문서 규격 | ADR·파일 책임·구현 계획 | 책임·모드·불충분 입력 대응 → 구현 |
| 구현 | 설계 기준 | SKILL.md·5개 참조·UI 메타데이터 | 유효한 메타데이터·경로·가상 예시 → 검증 |
| 검증 | 정확한 구현 판본·TC01–28 | 패키지 검사·직접 적용 결과·결함/미검증 | 기대와 관찰·형식과 의미를 구분 → 안내 |
| 사용 안내 | 실제 파일·검증 결과 | README·호출/설치 안내·출처 대장 | 기능·명령·파일 대응 → 공개 후보 |
| 인계 | 정확한 후보·검증·자료 목록 | 후보 목록·라이선스 권장안·잔여 조건 | 공개·라이선스·정식 릴리스의 실제 결정 |

설계는 MADR의 맥락·기준·대안·선택·영향·확인 흐름을 참고한다. 구현 계획과 요구사항 추적은 해당 프로젝트에 필요한 자체 표다. 검증 기록은 입력·판본·방법·실제 출력·관찰·결함·잔여 제한을 연결하고, 공개 결정은 대상·선택·영향·재개 조건을 채운다. 외부 템플릿 본문을 배포 패키지에 복제하지 않는다.

## 파일 책임

- `skills/korean-writing/SKILL.md`: 모드 해석과 공통 의미 계약, 필요한 참조 선택.
- `references/korean-language.md`: 문맥·높임·생략·부정·가능성의 표현 예시.
- `references/documents.md`: 목적별 문서 구성과 사용자 지정 양식.
- `references/messages.md`: 공유·요청·진행·결정 요청의 짧은 문구.
- `references/evidence.md`: 출처·해석·미확인·충돌·원문 오류 처리.
- `references/examples.md`: 자체 가상 사례와 유지 사례.
- 저장소 `scripts/`·`tests/`: 배포 구성 확인용 개발 도구. 스킬 사용에 실행을 강제하지 않는다.

## 완료 증거와 관리

변경을 단계별 커밋으로 남긴다. 검증 기록은 실제 검사와 작성자 직접 적용을 구분하며 독립 검토·자동 선택·다른 환경·효과 입증을 주장하지 않는다. 결함은 관찰·수정·재확인을 연결한다. 외부 공개 자료는 링크와 자체 요약·판본만 포함하고 내부 문서·Slack 원문·개인 경로·논문 PDF·타인 스킬 원문은 제외한다.
