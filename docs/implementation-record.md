# 구현 기록

작성: Codex, 2026-10-12 Asia/Seoul. 최초 계획에 대응하는 구현과 릴리스 변경을 기록한다.

## 구현한 행동

문장을 자연스럽게 다듬다가 가능성을 확정으로, 미확인을 성공으로, 질문을 지시로 바꾸는 오류를 다룬다. `SKILL.md`에 K01–K12 의미 보호 계약, 요청 모드, 입력 부족 처리, 결과 대조를 두었다. 문서·메시지·한국어 표현·근거·예시는 필요한 경우에만 읽는 참조 5개로 나눴다.

스킬은 핵심 지침 1개·참조 5개·UI 메타데이터 1개로 구성한다. 스킬 안에는 실행 스크립트·외부 MCP 의존성·회사 운영 정책이 없다. 저장소의 개발 스크립트는 구성 검사와 ZIP 생성에 사용한다.

## 요구사항과 대응

| 구현한 부분 | 요구/분기 | 확인할 내용 |
|---|---|---|
| 요청 모드와 결과 구분 | R1/R2, B01–B05 | 작성·수정·검토·결합 요청의 범위 |
| 의미 계약과 입력 부족 처리 | R3/R6/R7, K01–K12, B06–B09 | 주체·값 충돌·미확인·원문 유지 |
| 한국어 표현 참조 | R4 | 생략·부정·양태·격식의 문맥 |
| 문서·메시지 참조 | R5/R9, B10 | 목적별 구성·지정 양식·상태 |
| 근거·가상 예시 참조 | R3/R6/R7 | 사실/해석·인용·가상·유지 사례 |
| 상대 참조와 실행 경계 | R8, B11 | 회사 URL·개인 경로·특정 도구 의존 제외 |

계획의 통합 조건에 따라 `principles.md`의 공통 판단은 핵심과 문서 구성 참조에 포함했다. 파일 개수를 맞추기 위한 빈 자원은 만들지 않았다. 공식 템플릿 본문·타인 스킬 프롬프트·논문 전문은 재배포하지 않는다.

## 발견한 결함과 수정

| 식별자 | 관찰 | 수정과 재확인 |
|---|---|---|
| D-ENC-01 | Windows 기본 cp949에서 공식 quick_validate.py가 UTF-8 SKILL.md를 읽지 못함 | `python -X utf8`로 실행해 통과. 스킬 오류와 검사 환경을 구분함 |
| D-ENC-02 | 초기 생성 도구가 UI 메타데이터를 cp949로 저장함 | UTF-8로 재작성. 전체 파일 검사와 비UTF-8 거부 시험 통과. 의미 규칙은 유지함 |

실제 검사·직접 적용·그 밖의 결함은 [검증 보고](verification-report.md)에 있다. 형식 적합성을 독립 품질 평가나 개선 효과의 증거로 쓰지 않는다.

## v0.1.0 릴리스 변경

사용자의 후속 위임으로 공개·라이선스 확정·정식 릴리스를 진행했다. MIT 고지와 `license: MIT`를 추가하고, 빌드가 LICENSE를 함께 넣도록 수정했다. manifest는 version·license·release_channel·파일별 SHA256을 기록한다. 고지 누락과 메타데이터 불일치 거부 시험을 추가했다.

README·사용 안내·출처/권리 고지·공개 점검·DACI 인계·변경 기록을 같은 배포 구성에 맞췄다. 최초 후보의 7개 파일+manifest에 LICENSE를 더해 설치 ZIP은 8개 파일+manifest가 됐다. 격리된 프로젝트 폴더의 복사는 확인했고 사용자 전역 설치는 수행하지 않았다. 작성 지침의 본문과 참조 5개는 최초 구현 후보와 같다.

게시 결과와 정확한 판본은 [릴리스 인계](release-readiness.md)에, 이후 저장소 문서의 자기 적용 편집은 [문서 편집 기록](editing-record.md)에 연결한다.
