# 구현 기록과 계획 대비 결과

작성: Codex, 2026-10-12 Asia/Seoul.

## 문제와 구현 행동

원문을 자연스럽게 바꾸다가 가능성이 확정으로, 미확인이 성공으로, 질문이 지시로 바뀌면 글의 목적이 훼손된다. 핵심 파일에 K01–K12 의미 계약과 모드·입력 부족·최종 대조를 구현했다. 구체적인 문서·메시지·한국어 표현·근거·예시는 필요할 때만 읽는 다섯 참조로 나눴다.

핵심 지침 1개·참조 5개·UI 메타데이터 1개로 스킬을 구성한다. 스킬 안에 실행 스크립트·외부 MCP 의존성·회사 운영 정책은 없다. 저장소의 개발 스크립트는 구성 확인과 ZIP 후보 생성에만 사용한다.

## 변경과 설계 대응

| 구현 | 대응 | 확인 |
|---|---|---|
| SKILL.md 요청·결과 구분 | R1/R2, B01–B05 | 작성·수정·검토·결합 요청의 범위 |
| 의미 계약·불충분 입력 | R3/R6/R7, K01–K12, B06–B09 | 주체·값 충돌·미확인·원문 유지 |
| 한국어 표현 참조 | R4 | 생략·부정·양태·격식 문맥 |
| 문서·메시지 참조 | R5/R9, B10 | 목적별 구성·지정 양식·상태 |
| 근거·가상 예시 참조 | R3/R6/R7 | 사실/해석·인용·가상·유지 사례 |
| 상대 참조와 실행 경계 | R8, B11 | 회사 URL·개인 경로·특정 도구 의존 없음 |

독립 principles.md는 계획 단계의 통합 조건에 따라 핵심과 문서 구성 참조에 통합했다. 빈 파일을 개수에 맞추지 않았다. 공식 템플릿의 본문·타인 스킬 프롬프트·논문 전문을 재배포하지 않는다.

## 발견한 문제와 수정

- D-ENC-01: Windows 기본 cp949에서 공식 quick_validate.py가 UTF-8 SKILL.md 읽기에 실패했다. `python -X utf8`로 실행해 검사를 통과했다. 스킬 원문 오류와 검사 실행 환경을 구분한다.
- D-ENC-02: 초기 생성 도구가 UI 메타데이터를 cp949로 저장해 UTF-8 읽기에서 한국어가 깨졌다. 파일을 UTF-8로 다시 작성했고 전체 파일 검사·비UTF-8 메타데이터 거부 시험으로 확인했다. SKILL.md의 의미 규칙에는 변경이 없다.

실제 검사와 직접 적용 결과는 [검증 보고](verification-report.md)에 연결한다. 형식 적합성을 한국어 글쓰기 효과·독립 검토·자동 선택의 증거로 확대하지 않는다.
