# 공개 범위 확인 기록

작성·직접 확인: Codex, 2026-10-12 Asia/Seoul. 첫 정식 판본은 `v0.1.0`이다. 공개·라이선스 선택·정식 릴리스는 실제 사용자의 후속 위임에 따라 진행한다.

## 공개할 자료와 제외할 자료

저장소에는 자체 작성한 스킬·가상 예시·개발 스크립트·시험·문서, 외부 출처 69개의 링크와 자체 메모, 템플릿 284개 항목의 목적 분석을 둔다. 284개는 분석 항목 수이며 템플릿 전문 수집이나 각 항목의 독립 전수검증 수가 아니다.

회사 운영 정책·작업 계약·내부 문서/메시지 원문·계정/채널 식별자·개인 로컬 경로·인증정보·논문 PDF·다른 작성자의 스킬 코드/프롬프트·네이티브 템플릿 본문은 배포 대상에서 제외한다. 외부 출처의 링크와 자체 요약에는 원출처의 권리가 남는다.

Git 이력·브랜치·PR 제목/본문/댓글·Actions 실행 로그도 공개 범위에 포함한다. 기존 Git 작성자의 이름·이메일 메타데이터를 포함한 이력을 유지하며, 새 릴리스 커밋에는 GitHub `noreply` 주소를 사용한다. 공개 저장소 전환의 영향은 [GitHub 공식 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)를 확인했다.

## 확인 방법과 관찰

- 현재 파일의 UTF-8·상대 참조·저장소 경계·내부 URL/개인 경로 후보는 구성 검사로 확인한다.
- 공개 전 Git의 모든 로컬 참조에서 도달 가능한 커밋과 파일을 읽고, 알려진 GitHub/Slack/AWS 인증정보 형식·개인키·내부 URL·로컬 경로·자료 관리 식별자 패턴을 확인했다. PR와 완료된 CI 로그도 같은 범위로 읽었다. 알려진 민감 패턴은 발견하지 못했다.
- 과거 UI 메타데이터 한 판본에 cp949 파일이 있었다. 해당 역사적 파일도 읽기 변환하여 패턴을 확인했고, 현재 배포 판본의 UTF-8 수정과 거부 시험은 기존 결함 기록에 남긴다. 과거 실패 CI도 보존한다.
- 패키지 고지와 파일 해시를 확인하고, 게시한 태그·가시성·릴리스 속성·익명 다운로드 결과를 재조회한다. 실제 SHA와 CI는 [릴리스](https://github.com/monancho/korean-writing-skill/releases/tag/v0.1.0) 및 연결된 PR/Actions를 원본으로 사용한다.

이 확인은 작성자의 직접 확인과 알려진 패턴 검사다. 독립 보안 감사·모든 민감정보 부재 인증·외부 원출처의 법적 권리 확정은 수행하지 않았다. 새로운 결함이 발견되면 실제 영향 범위를 기록하고 수정 판본을 준비한다.

## 릴리스 경계

MIT는 자체 작성한 배포 파일에 적용한다. 설치 ZIP은 스킬 파일 7개와 `LICENSE`, 파일별 SHA256을 담은 `manifest.json`으로 구성한다. 함께 게시하는 `SHA256SUMS`는 ZIP 전체의 SHA256이다. GitHub의 소스 아카이브는 저장소 문서·시험을 포함하는 별도 자료다.

`v0.1.0`은 첫 정식 배포 판본이다. 독립적인 글 품질 평가·호스트 자동 선택·실사용 효과·제품 간 호환성 보증을 뜻하지 않는다. 확인한 사례와 미수행 범위는 [검증 보고](verification-report.md)에 구분한다.
