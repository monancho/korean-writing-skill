# 공개 범위 점검 기록

작성·직접 확인: Codex, 2026-10-12 Asia/Seoul. 사용자 위임에 따라 공개한 첫 정식 판본 v0.1.0의 자료 범위와 확인 방법을 기록한다. 실제 게시 결과는 [릴리스 인계](release-readiness.md)에 있다.

## 포함·제외 범위

| 범위 | 자료 |
|---|---|
| 포함 | 자체 스킬·가상 예시·개발 스크립트·시험·문서, 외부 출처 69개의 링크와 자체 메모, 템플릿 284개 항목의 목적 분석 |
| 제외 | 회사 운영 정책·작업 계약·내부 문서와 메시지 원문·계정/채널 식별자·개인 로컬 경로·인증정보·논문 PDF·타인 스킬 코드/프롬프트·네이티브 템플릿 본문 |
| 함께 공개되는 이력 | Git 이력·브랜치·PR 제목/본문/댓글·Actions 로그·Git 작성자 이름과 이메일 메타데이터 |

284개는 분석 항목 수다. 템플릿 전문을 수집하거나 각 항목을 독립적으로 전수검증한 수가 아니다. 외부 출처의 권리는 원출처에 남는다. 기존 작성자 메타데이터를 포함한 Git 이력은 유지했고 새 릴리스 커밋에는 GitHub noreply 주소를 사용했다. 공개 전환의 영향은 [GitHub 공식 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)를 확인했다.

## 확인 방법과 관찰

| 확인 | 방법 | 관찰·한계 |
|---|---|---|
| 현재 파일 | 구성 검사로 UTF-8·상대 참조·저장소 경계·내부 URL/개인 경로 후보 확인 | 구성 검사 통과. 알려진 패턴을 확인하는 보조 수단 |
| 공개 전 Git 이력 | 모든 로컬 참조에서 도달 가능한 커밋·파일을 읽고 알려진 GitHub/Slack/AWS 인증정보 형식·개인키·내부 URL·로컬 경로·자료 관리 식별자 패턴 확인 | 알려진 민감 패턴을 발견하지 못함 |
| PR·CI | 공개할 PR와 완료된 CI 로그를 같은 범위로 읽음 | 알려진 민감 패턴을 발견하지 못함. 과거 실패 CI 보존 |
| 과거 인코딩 | cp949였던 UI 메타데이터의 역사적 판본을 읽기 변환하여 확인 | 패턴 확인. 현재 배포 파일의 UTF-8 수정·거부 시험은 결함 기록에 남김 |
| 게시 자산 | 패키지 고지·파일 해시 확인 후 태그·가시성·릴리스 속성·로그인 없는 다운로드 재조회 | 실제 값과 링크는 릴리스 인계에 기록 |

이는 작성자의 직접 확인과 알려진 패턴 검사다. 독립 보안 감사, 모든 민감정보 부재 인증, 외부 원출처의 법적 권리 확정은 수행하지 않았다. 새 결함을 발견하면 실제 영향 범위를 기록하고 수정 판본을 준비한다.

## 배포 경계

MIT는 자체 작성한 배포 파일에 적용한다. 설치 ZIP은 스킬 파일 7개와 LICENSE, 파일별 SHA256을 담은 manifest.json으로 구성한다. 함께 게시한 SHA256SUMS.txt는 ZIP 전체의 해시를 담는다. GitHub 소스 아카이브는 문서와 시험을 포함하는 별도 자료다.

v0.1.0은 첫 정식 배포 판본이다. 독립적인 글 품질 평가·호스트 자동 선택·실사용 효과·제품 간 호환성 보증을 뜻하지 않는다. 실제 사례와 미수행 범위는 [검증 보고](verification-report.md)에 있다.
