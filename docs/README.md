# 개발 문서 안내

설계에서 구현·검증·공개까지의 판단과 실제 결과를 연결한다. 사용 방법이 필요하면 [사용 안내](usage.md)부터 읽는다.

| 확인할 내용 | 문서 | 읽을 때 구분할 것 |
|---|---|---|
| 스킬을 한 진입점과 다섯 참조로 나눈 이유 | [ADR-001](adr/0001-entrypoint.md) | 자체 설계 선택과 효과 검증 |
| 요구사항이 어디에 구현됐는지 | [요구사항 추적](requirements-traceability.md) | 규칙·분기·사례의 대응과 실제 관찰 |
| 구현 순서·파일 책임·인계 기준 | [구현 계획](implementation-plan.md) | 계획한 결과와 이후 실행 |
| 실제 변경과 발견한 결함 | [구현 기록](implementation-record.md) | 계획 대비 변경·수정·제한 |
| 실행한 검사·사례·미수행 범위 | [검증 보고](verification-report.md) | 자동 검사·작성자 직접 적용·독립 평가 |
| 포함한 자산과 출처의 역할 | [출처·자산 범위](source-and-assets.md) | 자체 자료와 외부 원출처의 권리 |
| 공개 전 무엇을 확인했는지 | [공개 점검](publication-review.md) | 직접 확인한 범위와 검사의 한계 |
| 공개·MIT·v0.1.0의 결정과 게시 결과 | [릴리스 인계](release-readiness.md) | 유효한 위임·실행·게시 후 재조회 |
| 이 스킬로 저장소 문서를 편집한 과정 | [문서 편집 기록](editing-record.md) | 실제 자기 적용과 품질 효과의 미검증 |

[변경 기록](../CHANGELOG.md)은 판본별 변경을, [조사 자료](../research/README.md)는 출처의 판본·열람 범위·자체 적용을 관리한다. 문서의 계획이나 기대 결과를 실행 증거로 대신하지 않는다.
